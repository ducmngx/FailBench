# FailBench Data Generation Pipeline

This document describes the full pipeline for generating failure contact datasets: from scene setup through trajectory planning, failure injection, and data output.

---

## Overview

The pipeline simulates a Franka Panda robot performing pick-and-place tasks, then injects failures (joint shutoff, gripper open, etc.) at various points along the trajectory. For each failure, it collects:

- **Pre-failure state**: RGB-D images from front + EE cameras, joint positions/velocities
- **Post-failure contacts**: 3D contact cloud with forces, geom pair IDs
- **Metadata**: failure mode, trajectory fraction, seed

The output is a dataset of `.npz` files + a `manifest.csv` for training contact prediction models.

---

## Prerequisites

### What you need to provide

1. **Scene XML** (`scenes/<scene_name>/scene.xml`)
   - MuJoCo MJCF defining: floor, table, obstacles, objects, cameras
   - Must include the robot via `<include file="panda.xml"/>`
   - Must define `front_cam` (static scene camera)
   - Objects to grasp should follow the `object3` naming convention

2. **Robot XML** (`franka_emika_panda/panda.xml`)
   - Already provided. 7-DOF Panda arm with parallel gripper
   - Includes `ee_cam` (wrist-mounted camera) and `end_effector` site
   - Copy into your scene directory if the scene XML uses `<include file="panda.xml"/>`

3. **Trajectory files** (`scenes/<scene_name>/trajs/*.pkl`)
   - Pre-computed RRT-Connect paths as pickled dictionaries
   - Structure: `{scene_name: {phase: {trajectory: List[np.ndarray(7,)]}}}`
   - Phases: `phase6` (approach), `phase7` (transport), or `baseline`
   - Generated by the RRT planner (see "Generating Trajectories" below)

### What the codebase provides

- Trajectory interpolation (sparse waypoints → smooth dense path)
- Failure injection (5 modes with configurable parameters)
- Multi-camera rendering (front + EE cam, RGB-D)
- Contact extraction and 3D→2D projection
- Batch experiment orchestration with manifest tracking

## Pipeline Architecture

```
Scene XML + Robot XML + Trajectory .pkl files
                    ↓
         generate_v9.py (entry point)
                    ↓
       BatchExperimentManager.generate_configs()
         → ExperimentConfig per (trajectory × seed)
                    ↓
       BatchExperimentManager.run_batch()
                    ↓
       ExperimentRunner.run()  [per trial]
         1. Load trajectory from .pkl
         2. Reset scene, grasp object3
         3. Interpolate trajectory (cubic spline, 50 pts/segment)
         4. Replay trajectory, inject failure at canonical fraction
         5. Capture pre-failure RGB-D + robot state
         6. Fork sim → inject failure → collect contacts (500 steps)
         7. Return DataSample
                    ↓
       save_sample_npz() + append_manifest()
                    ↓
       datasets/v9/
         ├── exp_00000.npz
         ├── exp_00001.npz
         ├── ...
         └── manifest.csv
```

## Key Components

### 1. Trajectory Interpolation

**File**: `planner/utils/trajectory_interpolation.py`

RRT planners produce sparse waypoints (typically 3 per phase). The interpolator converts these into dense, smooth trajectories using cubic spline interpolation:

- **50 points per segment** between consecutive waypoints
- **C2 continuity** (smooth velocity and acceleration)
- **Arc-length parameterization** for even spacing
- **Joint limit clamping** to prevent spline overshoot

This enables mid-motion failure injection where the arm has realistic nonzero velocity.

### 2. Failure Injection

**File**: `failure_injection/agressive_injector.py`

Five failure modes, with default probability weights:

| Mode | Probability | Description |
|------|------------|-------------|
| `gripper_open` | 0.35 | Gripper fully opens, drops object |
| `slippery_grip` | 0.25 | Reduced grip force, object may slide |
| `single_joint` (j4) | 0.15 | Joint 4 disabled, arm partially collapses |
| `single_joint` (j6) | 0.10 | Joint 6 disabled |
| `multi_joint` (j4+j6) | 0.10 | Two joints disabled simultaneously |
| `all_joints` | 0.05 | Complete arm shutdown, full collapse |

Joint failures zero out actuator gains, stiffness, damping, and friction — the joint becomes completely unactuated.

### 3. Failure Timing

Failures are injected at **canonical trajectory fractions**: `[0.1, 0.25, 0.4, 0.55, 0.7, 0.85]`

Each trial's seed determines which fraction is selected. This ensures:
- Coverage across the full trajectory (not just start/end)
- Meaningfully different arm configurations at each point
- No redundancy from sampling adjacent dense waypoints

### 4. Cameras

| Camera | Type | Description |
|--------|------|-------------|
| `front_cam` | Fixed, scene-level | Static front-right view (fovy=45). Primary for contact projection. Reproducible in a real lab with a tripod. |
| `ee_cam` | Wrist-mounted | Attached to link7, moves with arm (fovy=90). Close-up grasp view. Reproducible with a RealSense on the flange. |

Both capture RGB (uint8) and depth (float32) at configurable resolution (default 640×480).

### 5. Contact Extraction

**File**: `planner/experiments/data_capture.py`

`ContactExtractor` extracts contacts from MuJoCo's `data.contact` array each sim step:
- Filters out robot self-contacts (robot-vs-robot geom pairs)
- Applies force threshold (default 1N minimum)
- Returns 3D position, normal, 6D force, geom pair IDs

`ContactProjector` projects 3D contact points to 2D pixel coordinates for any named camera using the camera's intrinsics/extrinsics from the MuJoCo model.

## Running Dataset Generation

### Quick start (v9 — recommended)

```bash
conda activate failbench
python scripts/generate_v9.py
```

This generates 40 trials (4 trajectories × 10 seeds) with:
- Cubic spline interpolation
- Mid-motion failure injection
- One probabilistically sampled failure mode per trial
- Output: `scenes/scene_level2/datasets/v9/`

### Custom generation

Create a new script or modify parameters in `generate_v9.py`:

```python
from planner.experiments.manager import BatchExperimentManager

manager = BatchExperimentManager(output_dir="path/to/output", num_workers=4)

configs = manager.generate_configs(
    scene_xml_path="scenes/scene_level2/scene.xml",
    robot_xml_path="franka_emika_panda/panda.xml",
    trajectory_files=["path/to/traj1.pkl", "path/to/traj2.pkl"],
    num_trials_per_trajectory=20,
    base_seed=0,

    # Cameras
    camera_name="front_cam",
    extra_cameras=["ee_cam"],

    # Interpolation (set use_interpolation=False for legacy sparse mode)
    use_interpolation=True,
    interp_points_per_segment=50,
    interp_method="cubic",
    steps_per_interp_point=4,

    # Failure selection
    failure_sample_mode="sample",  # "sample" = one mode per trial, "all" = every mode
    num_failure_samples=1,
)

manifest_path = manager.run_batch(configs)
```

### Legacy mode (v7/v8 compatible)

Set `use_interpolation=False` (default) to use sparse waypoint replay with 200-step settling. This reproduces the behavior of earlier dataset versions.

## Output Format

### NPZ file contents

Each `.npz` file contains one trial:

| Key | Shape | Type | Description |
|-----|-------|------|-------------|
| `pre_rgb` | (H, W, 3) | uint8 | Pre-failure RGB from front_cam |
| `pre_depth` | (H, W) | float32 | Pre-failure depth from front_cam |
| `ee_cam_rgb` | (H, W, 3) | uint8 | Pre-failure RGB from ee_cam |
| `ee_cam_depth` | (H, W) | float32 | Pre-failure depth from ee_cam |
| `post_rgb` | (H, W, 3) | uint8 | Post-failure RGB (final frame) |
| `pre_qpos` | (7,) | float64 | Joint positions at failure |
| `pre_qvel` | (7,) | float64 | Joint velocities at failure |
| `pre_ee_pos` | (3,) | float64 | End-effector position |
| `pre_gripper_ctrl` | (1,) | float64 | Gripper control value |
| `pre_qvel_norm` | (1,) | float64 | Joint velocity magnitude (rad/s) |
| `contact_positions` | (N, 3) | float32 | 3D contact positions |
| `contact_forces` | (N, 6) | float32 | Contact forces (3 force + 3 torque) |
| `contact_geom_pairs` | (N, 2) | int32 | Geom IDs of contacting bodies |
| `contact_failure_id` | (N,) | int32 | Which failure mode produced each contact |
| `failure_modes` | (M,) | str | Failure mode names |
| `failure_probs` | (M,) | float32 | Sampling probabilities |
| `impacted_geom_ids` | (K,) | int32 | Unique geom IDs that were contacted |
| `fail_phase` | (1,) | int32 | Phase (6 or 7) |
| `fail_step` | (1,) | int32 | Dense trajectory point index |
| `seed` | (1,) | int32 | Random seed |

### Manifest CSV

`manifest.csv` provides a quick overview of all trials:

```
experiment_id, trajectory_file, seed, fail_phase, fail_step,
num_contacts, num_failure_modes, had_any_collision,
impacted_geom_ids, pre_qvel_norm, npz_file
```

## Generating New Trajectories

If you need trajectories for a new scene:

1. **Define the scene** in `scenes/<name>/scene.xml` with obstacles and pick/place sites
2. **Use the RRT planner** (`planner/algorithms/RRTplanner.py`):
   - `JointSpaceRRTConnect` plans collision-free paths in joint space
   - Requires start config, goal config, and collision checker
3. **Save trajectories** via `ExperimentTrajectoryManager`:
   ```python
   from planner.utils.traj_saver import ExperimentTrajectoryManager
   mgr = ExperimentTrajectoryManager()
   mgr.store_trajectory("scene_name", "phase7", waypoints, goal_pos=target)
   mgr.save_to_file("scenes/<name>/trajs/<name>_RRTConnect.pkl")
   ```
