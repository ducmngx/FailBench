# LIBERO v1 dataset

Failure-injection contact dataset built by replaying LIBERO teleop demos and
forking sim state at sampled progress points. Sibling of the v10 main-pipeline
dataset; npz schema is identical apart from the new `pre_target_qpos` field.

Generated by `scripts/libero/run_libero_dataset.py` over ~10.8 h on 8 workers
(1.18 trials/s). Driver design and the active-resistance settle are documented
in `docs/libero_failure_injection.md`.

## Volume

| Split          | Trials | Tasks | Demos/task | Seeds | Bins/(demo,seed) |
|----------------|--------|-------|------------|-------|------------------|
| libero_spatial | 15,000 | 10    | 50         | 3     | 10               |
| libero_object  | 15,000 | 10    | 50         | 3     | 10               |
| libero_goal    | 15,000 | 10    | 50         | 3     | 10               |
| **TOTAL**      | **45,000** | **30** | — | — | — |

On disk: 90.9 GB across 45,000 npz files. Manifests at
`datasets/libero/v1/<split>/manifest.csv` (15,000 rows each).

`bin_idx` indexes one of 10 equal sub-ranges of `traj_progress ∈ [0.05, 0.9]`;
within a bin the actual `traj_progress` is drawn uniformly. `seed` is hashed
deterministically from `(base_seed, split, task, demo_key, seed_idx, bin_idx)`,
so the same set is reproducible from a fresh git clone.

## Failure-mode distribution

Driven by `_default_failures()` in `planner/experiments/libero/runner.py`. One
sampled failure per trial.

| Mode          | Count  | Share |
|---------------|--------|-------|
| SINGLE_JOINT  | 19,255 | 42.8% |
| GRIPPER_OPEN  | 11,337 | 25.2% |
| SLIPPERY_GRIP |  6,766 | 15.0% |
| MULTI_JOINT   |  4,024 |  8.9% |
| ALL_JOINTS    |  3,618 |  8.0% |

Joint specificity (SINGLE/MULTI_JOINT only):

| Joints           | Count | Share |
|------------------|-------|-------|
| j2 (shoulder)    | 8,090 | 18.0% |
| j4 (elbow)       | 5,706 | 12.7% |
| j6 (wrist pitch) | 3,205 |  7.1% |
| j2+j4            | 2,274 |  5.1% |
| j4+j6            | 1,750 |  3.9% |
| j1 (base yaw)    | 1,328 |  3.0% |
| j7 (wrist roll)  |   926 |  2.1% |

Pitch joints (j2/j4/j6) carry most of the planner-relevant signal because they
load gravity. j1 and j7 are kept at low weight for diversity. j3 and j5 are
intentionally omitted — their failure signature is too subtle to be worth the
trial budget.

100% of trials produced ≥1 contact during the post-failure settle (median
2,019 contacts/trial, max 29,409). Contacts are sampled at every settle step
across 500 steps, so the same physical contact gets recorded many times — fine
for density targets, requires dedup for per-event analyses.

## Per-trial features (inputs)

Captured at the moment of failure injection, before any failure mode is applied.

| Field              | Shape         | Dtype | Description |
|--------------------|---------------|-------|-------------|
| `pre_qpos`         | (7,)          | f64   | Arm joint positions |
| `pre_qvel`         | (7,)          | f64   | Arm joint velocities (≈0 — kinematic replay zeroes velocity) |
| `pre_ee_pos`       | (3,)          | f64   | End-effector world position |
| `pre_gripper_ctrl` | (1,)          | f64   | Mean finger qpos as a scalar |
| `pre_target_qpos`  | (7,)          | f64   | Demo's commanded qpos at fail step (resistance hold target) |
| `pre_rgb`          | (480, 640, 3) | u8    | `agentview` RGB |
| `pre_depth`        | (480, 640)    | f32   | `agentview` depth (m) |
| `robot0_eye_in_hand_rgb`   | (480, 640, 3) | u8 | Wrist camera RGB |
| `robot0_eye_in_hand_depth` | (480, 640)    | f32 | Wrist camera depth |
| `traj_progress`    | (1,)          | f32   | Failure point in [0.05, 0.9] of demo |

Indexing: `task_id="<split>__<task>"`, `traj_id` (demo index), `seed`. Manifest
adds `split`, `demo_key`, `bin_idx`.

## Per-trial labels (outputs)

Produced by the post-failure settle (500 sim steps; healthy joints driven by
gravity comp + per-joint PD toward `pre_target_qpos`; failed joints limp).

| Field                | Shape         | Dtype | Description |
|----------------------|---------------|-------|-------------|
| `contact_positions`  | (N, 3)        | f32   | World-space contact points |
| `contact_forces`     | (N, 6)        | f32   | 3D force + 3D torque per contact |
| `contact_geom_pairs` | (N, 2)        | i32   | (geom1, geom2) MuJoCo IDs |
| `contact_failure_id` | (N,)          | i32   | Index into `failure_modes` (always 0; 1 mode/trial) |
| `impacted_geom_ids`  | (M,)          | i32   | Sorted union of geoms touched |
| `failure_modes`      | (1,)          | str   | Mode name |
| `failure_probs`      | (1,)          | f32   | Prior weight of this mode |
| `post_rgb`           | (480, 640, 3) | u8    | `agentview` RGB after settle |

### Derivable label forms

| Label form | How |
|-----------|------|
| 2D contact-density heatmap | `scripts/build_density_targets.py` recipe — per-scene grid, prior-weighted, Gaussian-blurred. Needs per-task scene-table-z handling for LIBERO. |
| Per-entity risk score | `entity_footprints × heatmap → Σᵢ score(eᵢ)·S(eᵢ)` (paper formulation). Implemented in `planner/risk/spatial.py`. |
| Worst-impacted entity | `argmax` of per-entity score (multiclass classification target). |
| Region-of-impact overlay | `ContactProjector` projects (x,y,z) into camera frames; used in `notebooks/eval_model.ipynb`. |
| Binary collision indicator | Always 1 in v1 (every trial collided) — degenerate; only useful once v2 adds non-failure baselines. |

## What each split contributes

- **spatial** — fixed objects, varied object positions per task. Trains spatial generalization.
- **object** — fixed positions, varied object identities. Trains object/geometry invariance.
- **goal** — varied goal regions (different transport directions). Trains direction-conditioned risk; most planner-relevant.

## Caveats for training

1. **One failure mode per (demo, seed, bin)** — per-config supervision of the
   prior-weighted heatmap is single-sample. Aggregate over the (seed × bin ×
   demo) manifold for stable targets, or bump `num_failure_samples` in v2.
2. **`pre_qvel ≈ 0`**. Kinematic replay zeroes velocity at every step. Derive
   motion features from raw HDF5 `obs/joint_states[t-1] vs t` if needed.
3. **Limited unique scene templates**: 30 LIBERO tasks share ~10 underlying
   scene layouts (especially within `spatial`). RGB-conditioned models see
   less geometric diversity than the trial count suggests.
4. **Contacts are time-accumulated** across 500 settle steps. Density targets
   handle this naturally; event-level analyses need temporal dedup.

## Tooling

- Generate (idempotent, supports `--resume`):
  ```bash
  conda run -n failbench_env python -m scripts.libero.run_libero_dataset \
    --splits libero_spatial libero_object libero_goal \
    --output_dir datasets/libero/v1 \
    --seeds 3 --progress_bins 10 --workers 8 --resume
  ```
- Patch a manifest from disk (e.g. after a kill-time row loss):
  ```bash
  python -m scripts.libero.rebuild_manifest --split libero_spatial
  ```
- Inspect one trial: `notebooks/inspect_libero.ipynb` (entity-level baseline
  filtering for clean contact clouds).
